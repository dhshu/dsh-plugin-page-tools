# 插件页搜索、分页与全部更新

Host 半边（`lib/index.js`）不提供任何能力，浏览器半边（`lib/client.js`）只改变呈现，不改动宿主行为。

插件页保持官方版式。本插件在「已安装插件」分组（`data-plugin-group="bundles"`）的标题正下方放一个搜索框，在卡片之后放一行靠右排列的内容：「第 1–10 条，共 25 条」、「每页 N 条」、页码，整行贴着行的右端；并在页头工具条「刷新」按钮右边放一个「全部更新」按钮。

## 一、搜索与分页

- **搜索**匹配卡片的标题、简介和包名，大小写不敏感、空白折叠、按空格切词，要求每个词都出现；匹配数量（`9/25`）显示在搜索框右侧。
- **每页条数**默认 10 条，可改成 1–100 之间的任意整数，回车或失焦生效并记在本机（`localStorage` 的 `dsh-plugin-page-tools.page-size`）。改条数时保持当前屏幕上第一张卡的位置，不跳回第一页。
- **分页器**在这一行的最右边：首页、上一页、当前页附近以及首尾的页码、下一页、末页。只有一页时不显示页码按钮，只留条数和区间；查询无结果时隐藏卡片列表，改为显示「没有匹配「…」的插件。」。
- 官方页面每次重新渲染卡片都会重新应用一次视图，所以启用插件、刷新列表、切换标签都不会清掉搜索词和页码。

## 二、全部更新

「刷新」按钮右侧的「全部更新」按钮上带着 `N`：插件管理器认为有更新的插件有几个。点它就把这几款插件逐个更新，全程没有额外对话框。

- 判定与页面自己的「可更新」一致：包来自安装源（`registry`）、最新可用版本不是预发布也不是已弃用，且声明为 bundle、与当前 DSH 兼容。
- 逐个进行：一次装完再装下一个，失败互不影响；失败的插件在同一次会话里不会被重复尝试，装好的照常保留。官方更新本身仍由宿主执行，失败时回滚旧版本的那套逻辑不变。
- 运行期间按钮禁用，悬停提示显示「正在更新 <插件名>（2/3）」；结束提示「已更新 N 个插件」或「已更新 N 个，M 个失败」。没有可更新插件时按钮是禁用态。

### 页面上下文

「全部更新」需要读宿主列出的版本、并调用宿主的更新动作，而这两样只出现在插件页自己的上下文里。所以本插件按官方约定注册了一个 `plugins.tab` 标签页——这是获得页面上下文的正式入口；标签页内容只是一行说明，按钮仍然在「已安装」页头。更新与检查都走宿主自己的 `listBundles`、`listVersions`、`updateBundle`，与页面的「版本」区域同一套调用。

## 配置

无。本 bundle 不提供服务、工具或配置项。

## 说明

- 自有类名前缀 `dship-`，自有 DOM，只用主题变量（`--dsw-alias-*`、`--dsw-radius-*`、`--dsw-focus-ring-*`）。
- 文案通过 `ctx.locale` 注册 `zh` 与 `en`；插件展示信息在 `locale/zh.json`、`locale/en.json`。
- 浏览器半边不能 `require('react')` 一类的宿主包：页面的模块加载器只认宿主自己提供的模块和引导图里的包。本插件因此不引用任何 React，只用原生 DOM。
